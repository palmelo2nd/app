## 1. タスク管理タブ

タスクの親子関係を「親ID」1本で表現する中心画面。旧・繰返し／旧タスク整理／タスク実行／プロジェクト／勤務の5タブを統合したもので、フィルタ〜カレンダー〜1日タスク〜編集フォームまでを常時表示のまま、上部の表示切り替えで6つのビューを切り替える。DOM上のIDプレフィックスは `taskorg2-` / `calendar2-` / `dayedit2-`。

### 1.0 クイック登録（旧INBOX）

タスク管理タブの最上部（フィルタの上）にある、既定で閉じたExpander。思いついたことを手早く登録するための入口（2026-10-28に旧INBOXタブから移設）。

- テキストエリアに内容を入力し「登録」ボタンで、通常のタスクとして即座に1件保存する。タイトルは入力内容の先頭15文字、IDは既存の最大ID+1で自動採番。
- カテゴリは画面上部で選択中のカテゴリ（「すべて」の場合は空欄）を自動設定。ステータス・優先度・開始予定・終了予定などは空欄のまま登録する。
- そのため登録した行は[1.11](#111-未設定対応中対応待ち属性未設定タスクなどの一覧)の「属性未設定タスク」に必ず出てくる。ここがINBOXの代わりで、後からステータス・日付などを整える。
- 登録後はGitHubへの送信を待たずLocalStorageに即時保存される（[添付C](#c-データ読み書きオフライン対応)参照）。

### 1.1 表示切り替え（カレンダー／ガントチャート／習慣／勤務歴／プロジェクト／報告／AI確認）

画面上部のサブタブで7ビューを切り替える。年月・選択日（`taskorg2CalendarYear`/`Month`、`selectedTaskorg2Date`）はカレンダー・ガントチャート・習慣（月表示）・勤務歴の間で共有される。

### 1.2 フィルタ

- 画面上部（および[1.15 タスク一覧](#115-タスク一覧)直上）の「フィルタ」を展開すると、タグ／ステータスの複数選択と、「その他フィルタ」（プロジェクト／繰返しテンプレート／繰返し実行タスクの表示ON/OFFチェックボックス）を表示する。上下2箇所は同じ状態を参照する複製なので、どちらを操作しても同期する。
- 「その他フィルタ」の下に、プロジェクト（複数選択）で選んだものを起点にPJ(1層)→PJ(2層)…と辿れるドリルダウン用プルダウンを配置し、階層を絞り込んで子孫タスクだけに絞り込める。
- 以降のカレンダー・ガントチャート・習慣・プロジェクトツリー・タスク一覧はすべてこのフィルタが適用された結果を対象にする。

### 1.3 カレンダービュー

月間グリッドに、その日の勤務区分（[1.6 勤務歴](#16-勤務歴)の例外設定があればそちらを優先）を背景色で反映しつつタスクを表示。日をクリックするとその日を選択し、下の[1.10 日別タイムライン](#110-日別タイムライン1日タスクdayplan)に反映する。

### 1.4 ガントチャートビュー

表示単位「日」「週」を切替可能。ステータス別配色（未着手／進行中／中断等／連絡待ち・報告待ち／完了）で日付列にマーカー表示し、日付列クリックでその日を選択、行クリックで編集対象に切り替える。

### 1.5 習慣（週／月／毎日）

繰返し親タスク（テンプレート）を、頻度設定に応じて視覚的に配置する表示専用ビュー（クリックで右の[編集フォーム](#113-編集フォームタイマー機能含む)に読み込む点は他ビューと同じ）。表示単位「週」「月」「毎日」をボタンで切り替える。

| 単位 | 対象・表示 |
|---|---|
| 週 | 「頻度（曜日）」を設定している親タスクを、月〜日の固定表（曜日名の一致のみで判定、日付非依存）に表示 |
| 月 | 「頻度（日）」または「頻度（月）」を設定している親タスクをカレンダーの該当日に表示。日＋月の両方設定＝月が一致する時だけ／日のみ＝毎月その日／月のみ＝日付を特定できないためカレンダー下の「日付指定なしタスク」に表示 |
| 毎日 | 「頻度（曜日）」または「頻度（日）」の選択肢がマスタ定義の全選択肢を満たしている（＝実質「毎日」指定）親タスクを表示。週・月タブ側ではこの分を除外する |

いずれの単位でも、頻度（月・日・曜日）がすべて未設定の親タスクは「頻度未指定タスク」として別枠に表示する。

### 1.6 勤務歴

出勤日・休日・有給・特別休暇などの勤務区分をカレンダー形式で管理する（旧「勤務タブ」をそのまま移植）。

- 年・月それぞれに `‹` `›` ボタンで移動。
- 月間グリッドに、既定の曜日パターン、または個別の例外設定があればそちらを優先して色分け表示。例外設定がある日は専用マークを表示。
- 月次サマリー：表示中の月について区分ごとの日数を集計表示。
- 月一括編集フォーム：1日1行のテーブルで種別（デフォルトのまま／出勤日／休日／有給／特別休暇）と備考を入力し、「月一括適用」ボタンでまとめて保存する（種別が「デフォルトのまま」の行は例外設定から除外＝既定の曜日パターンに戻る）。
- ここで設定した勤務区分は、[1.3 カレンダービュー](#13-カレンダービュー)・[1.4 ガントチャートビュー](#14-ガントチャートビュー)（日単位）の非稼働日表示にも反映される。

### 1.7 プロジェクト（ツリー表示）

「親ID」で表現された階層構造全体を、折りたたみ可能なインデント付きツリーで一覧表示する（旧・独立した「プロジェクトタブ」の階層ブラウザ／階層整理は廃止され、このツリー1つに統合されている）。

- 各行はステータス別（完了→報告待ち→連絡待ち→中断→進行中→未着手→未設定の順）にグループ化されて並び、直属の子だけでなく孫以降も含めた子孫総数をタイトル横に表示する。既定では「ステータス=完了」の親だけを折りたたんでおき、手動で開閉した状態は行ごとに記憶する。
- 行クリックで右の[編集フォーム](#113-編集フォームタイマー機能含む)に読み込む。行頭のチェックボックスは複数選択用（本章末尾のPJ一括編集参照）。
- **PJ一括編集**：ツリーに限らず、[1.11](#111-未設定対応中対応待ち属性未設定タスクなどの一覧)・[1.12](#112-繰返しタスク)・[1.15](#115-タスク一覧)のチェックボックス付き一覧を横断してチェックした全タスクへ、ここで選んだPJ(n層)階層プルダウンの親IDだけを一括適用するボタン。「＋ 新規PJを追加」でその場に新規プロジェクトを作成して選ぶこともできる。タイトル・ステータスなど他の属性には一切触れない。
### 1.8 報告

テーマ（例：DSS）ごとに記録した成果を、どの報告先（会議・月報など）へいつ報告するかを一覧で管理する画面（2026-09-15新設、2026-10-14に「テーマ × 報告先のマトリクス」へ再設計）。DOM上のID `report-`。登録データは通常の`mainData`行を流用し、システム列 `{ 種別: '報告', 報告区分: … }`（`構造`／`テーマ`／`エントリ`／`タイミング`）で行種別を区別する。報告先・所属テーマ・報告先ごとの状態も、同じシステム列の`報告先`／`テーマID`／`報告状態`に持つ（2026-10-28まではInput・Output列）。テーマはタスクの親ID階層とは独立で、タスクとして登録していない成果も記録できる。

- **クイック追記**：テーマを選んで成果を書き「＋ 追記」（Ctrl+Enterでも可）。選んだテーマの既定報告先がすべて「予定」になる。テーマは「＋ 新しいテーマを作成…」からその場で作れ、前回選んだテーマは記憶される。
- **成果一覧（マトリクス）**：行＝成果（テーマごとにグループ化・折りたたみ可）、列＝報告先（見出しに次回の報告日を表示）。セルをタップすると 空 → 予定 → 済（今日の日付）→ 見送り → 空 の順に切り替わる。同じ成果が複数の報告先に並ぶことができ、報告先ごとに「済」の日付が1つ残る。成果の文章をタップするとその場で編集（テーマ変更・削除も可）。「未完了のみ」で予定・見送りが残る成果だけに絞れる。
- **報告先の準備画面**：マトリクスの列見出しをタップすると開く。報告日の追加・選択、その報告先で予定の成果（個別に「済」「見送り」「予定を外す」、または「予定をすべて報告済みにする」）、選択した日付の報告済み成果、下書き（「予定の成果から下書きを作成」でテーマ別の箇条書きを自動生成）、日付の削除ができる。
- **報告先・テーマの設定**（閉じた欄）：報告先は1行1件のテキストで編集（`[sN]`はID、省略時は自動採番）。テーマは名称変更・削除と、追記時に自動で「予定」にする既定の報告先を設定できる。
- 旧形式（タグ方式）のエントリは読込時に自動でテーマ「未分類」へ移行され、旧タイミングの備考にあった「報告／見送り」は状態へ引き継がれる。


### 1.9 AI確認

AI秘書（Claude）が会話から仮登録したタスクを確認する画面（2026-10-27新設）。DOM上のID `aireview-`、ロジックは`js/modules/aiReview.js`。

- 対象は`AI原案`列を持つ行。`AI原案`にはAI秘書の登録時点の値（親ID・タイトル・カテゴリ・ステータス・優先度・開始予定・終了予定・登録日）をJSONで保持し、アプリ側では書き換えない。
- 各行に所属パス・AI登録日と、状態バッジ（未確認／修正あり／そのまま）を表示する。「修正あり」は保存せず、現在の値と`AI原案`の比較で都度判定し、差分（例：`所属: A > B → C > D`）を行の下に表示する。
- 行をクリックすると下の編集フォームで開き、移動（親IDの変更）や修正ができる。プロジェクト一括編集での移動も同様に差分として拾われる。
- 「確認済」ボタン（行ごと）または、チェックした行の「選択を確認済にする」で`AI確認`列に`確認済 yyyy/mm/dd`を記録する。
- 表示の絞り込み：未確認（既定）／確認済／全件。
- AI秘書側は、修正の傾向（どの所属からどこへ移されたか）を集計して登録ルールの改善に使う。

### 1.10 日別タイムライン・1日タスク（DAYPLAN）

- 0:00〜24:00を縦軸にしたタイムラインに、選択日の「開始予定・終了予定に時刻が入力されているタスク」をブロック表示する。横軸は常に**固定4列**（縦の点線で区切りを表示）で、列1＝開始予定・終了予定が既に時刻まで決まっている「拘束される予定」の定位置、列2〜4＝時間未定タスクを手動またはドラッグで置いていく作業枠。ブロックには常に細い黒枠が付き、選択中のブロックは太い黒枠になる。チップにはタイトルのみ表示する（時刻は表示位置で分かるため非表示。対応中タスク一覧などのチップでは引き続き時刻を表示する）。
- 未確定タスクや、1日タスクのブロックとして参照済みのタスクは通常枠に出さず、[1.11](#111-未設定対応中対応待ち属性未設定タスクなどの一覧)側に振り分ける。
- **ドラッグ操作**：縦方向で時刻を変更（15分単位にスナップ）、横方向で列を変更できる。端のハンドルをドラッグするとリサイズ（所要時間の変更のみ、列は変わらない）。列2〜4で他のブロックと時間が重なった場合は、衝突した既存ブロックの直後へ自動的にずらして配置し、その結果さらに後続のブロックと重なればそれも連鎖的に押し出して解消する。押し出しの結果どれかが24:00を超える場合は、ドロップ操作自体をキャンセルする（列1は重なりを気にせずそのまま配置する）。まだ1日タスクに追加していないタスクを列方向にドラッグすると、その時点で1日タスクへ追加（昇格）される。
- **1日タスク（DAYPLAN）**：選択日ごとに1件、その日のスケジュールをテキストで管理する特殊行（詳細仕様は[添付E](#e-1日タスクdayplanの共通仕様)）。未作成の日は「1日タスクを作成」ボタンで新規作成し、その日既に時刻指定済みの既存タスクを自動的に取り込んで列1のブロックにする（既定は「09:00-09:30 メールチェック、予定整理」を含む）。「保存」でテキスト内容を反映、「1日タスクを削除」でその日の1日タスク自体を削除。
- [1.11](#111-未設定対応中対応待ち属性未設定タスクなどの一覧)などのチップの＋ボタンで1日タスクへ追加する際、開始予定・終了予定が既に決まっているタスクは列1へ、時間未定のタスクは列4へ9:00起点30分刻みで次の空き枠を自動的に割り当てる（重なりの押し出しは行わず、空いている枠を探すだけ）。
- タブを開いた時点では常に「今日」が選択された状態になる。

### 1.11 未設定／対応中／対応待ち／属性未設定タスクなどの一覧

いずれも現在のフィルタ・カテゴリ適用後の一覧をチップ形式で表示し、クリックで編集対象に選択できる（既定は折りたたみ）。チップ左のチェックボックスは複数選択（[PJ一括編集](#17-プロジェクトツリー表示)と、[1.13 編集フォーム](#113-編集フォームタイマー機能含む)の一括編集の対象）、チップ左端には優先度ドット（高＝赤／中＝黄／低＝緑）を表示する。「1日タスクに追加済み」一覧を除くすべてのチップに、[1.10](#110-日別タイムライン1日タスクdayplan)の1日タスクへ追加する＋ボタンを配置しており、状態を問わずどのタスクも1日タスクに追加できる。

| 折りたたみ項目 | 内容 |
|---|---|
| 対応中タスク（期間内） | 選択日について、未設定（時間帯未定）タスクと、1日タスクに追加済み（参照済み）のタスクを分けて表示。期間＝開始予定〜終了予定 |
| 対応待ちタスク（期間外） | 連絡待ち／報告待ち／中断のうち、開始予定・終了予定がともに入力済みで、今日がその期間内ではないタスク |
| 属性未設定タスク | カテゴリ／ステータス／優先度／プロジェクト（親ID未設定）／日付（開始予定・終了予定のいずれかに日付部分が無い＝空欄または時刻のみ入力）のいずれかが未入力のタスクを領域別に表示（重複表示あり） |

### 1.12 繰返しタスク

繰返し親タスク（テンプレート）と、そこから生成された実行タスク（子タスク）を左右に分けて操作するExpander（既定は折りたたみ、パフォーマンスのため開いている時だけ再描画する）。[1.5 習慣](#15-習慣週月毎日)が「頻度に沿った視覚的な配置」に特化しているのに対し、こちらは「実行タスクの生成・選択」に特化している。

- **テンプレート（左）**：登録済みの繰返し親タスクをチップで一覧。頻度が今日に該当するものを赤枠で強調し、子タスクが多いものほど上に表示。チップ右の「＋」ボタンで、「基準日」入力欄の日付を基準に実行タスクを「進行中」ステータスで生成する（既に生成済みの日付分は生成しない）。
- **実行タスク（右）**：選択中テンプレートの子タスクを基準日の新しい順にチップで一覧。チェックボックスで複数選択できる（[PJ一括編集](#17-プロジェクトツリー表示)対象）。
- **実績グラフ**：選択中テンプレートの子タスク実績（完了日 or 作成日時 × 実績時間）を折れ線グラフで可視化（Chart.js使用）。既定は非表示で「実績グラフ」ボタンで表示切り替え。

### 1.13 編集フォーム（タイマー機能含む）

親タスク・子タスク・通常タスクいずれを選択した場合も同じフォームを使うが、一部の項目は選択内容に応じて表示が切り替わる。「新規登録」ボタンでフォームをリセットし新規登録モードへ（この場合のみ日付を空欄のままにする。それ以外はカレンダー等で選択中の日付を初期値にする）。

| 項目 | 内容 |
|---|---|
| ID / タイトル / 内容 | 基本情報 |
| カテゴリ・タグ | マスタ選択式 |
| 親（プロジェクト） | ID・タイトルで検索して任意の階層に紐付けるPJ(n層)階層プルダウン。「＋ 新規PJを追加」でその場に新規プロジェクトを作成可能。「親を解除」で親なしに戻せる |
| ステータス | ステータス選択。「完了」に変更すると、完了日が未入力の場合のみ自動的に本日にする（既に入力済みなら上書きしない） |
| 優先度 / 見積時間（分） / 実績時間（分、読取専用） | 通常のタスク属性 |
| 開始予定・終了予定・完了日 | 日付＋時刻（時／分）。開始予定の日付を入力すると終了予定の日付に同じ日付を自動セット。開始予定の時（時間）を入力すると、開始予定の分を0に、終了予定を「時+1・分0」に自動セット（日付をまたぐかどうかは判定しない、いずれも手動修正可）。「開始/終了リセット」ボタンで開始予定・終了予定（日付・時・分）をまとめて空欄に戻せる。「開始/終了に反映」ボタンで完了日の値を、空欄になっている方だけに代入できる |
| 繰り返し（チェックボックス） | オンにすると、このタスクを繰返しタスクの親として扱い、頻度（月・日・曜日）の入力欄と、下記「実行タスクテンプレート」欄を表示する（OFF時は備考欄を表示） |
| 実行タスクテンプレート | **繰り返しON時のみ表示**。1回の生成で複数の実行タスクを作成できるようテンプレートを複数登録可能（開始予定・終了予定は基準日からのオフセット日数、タイトル接尾辞、内容を行ごとに指定）。実体は備考欄にJSON文字列として保存される |
| 備考 | **繰り返しOFF時のみ表示** |
| タイマー | **ステータスが「進行中」の既存タスクを選択中のみ表示**。`▷`／`■`でタイマー開始・停止（打刻はタイムスタンプログに追記、実行中は開始ボタンを無効化）。累計時間はライブ更新、「補正時間」欄で分単位の加減算が可能。タイムスタンプログはテキストエリアで直接編集可 |

- **操作ボタン**：「新規」（登録モードへリセット）／「適用」（変更を保存）／「削除」（選択中タスクを削除）。
- **一括編集**：タスク一覧・属性未設定タスクなどのチェックボックスで複数のタスクを選んでいる間は、「適用」「削除」が選択中の全タスクに対して働く。
  - 「適用」は、フォームにタスクを読み込んだ時点から**変更した項目だけ**を、選択中の全タスクへ反映する（変更していない項目は各タスクの値のまま）。反映前に、対象件数と反映する項目名を確認ダイアログで表示する。
  - 一括編集中は、フォーム上部に「N件を一括編集中」の案内を表示し、変更した項目の入力欄に背景色（黄色）を付ける。
  - 2026-10-28以前は、フォームの全項目（タイトル・内容を含む）を選択中の全タスクへ書き込んでいたため、表示中の1件の値で他のタスクのタイトル・内容まで上書きされる不具合があった。
- **グループに適用**（繰返し基準日を持つ子タスク選択時のみ表示）：開始予定・終了予定の変更差分（両方変更時は開始予定側優先）を日数差分として算出し、同じ回（同じ親ID＋繰返し基準日）の他の子タスク全体を平行移動する。

### 1.14 プロジェクト管理（一覧テーブル）

登録済みの全プロジェクト（配下タスク件数の多い順）を1行1件で表示する管理者向けテーブル（旧・独立した「プロジェクトタブ」の一覧機能のみを残したもの。タスク管理タブ内のExpanderとして常駐）。

| 操作 | 内容 |
|---|---|
| 状態 | 表示中／非表示中をボタンでトグル（非表示にすると各タブのプロジェクト選択肢から除外される） |
| 名前変更 | プロジェクトのタイトルをその場で変更 |
| 統合 | このプロジェクトを他のプロジェクトへ統合する。直属の子は全て統合先の子に付け替わり、自身も統合先の子（通常タスク）に降格する。循環参照になる統合は拒否 |
| 削除 | 直属の子がある場合、削除確認時に「別プロジェクトへ付け替え」または「未割り当て（単独タスク）にする」を選んでから削除 |

### 1.15 タスク一覧

画面下部に常時表示。現在のフィルタ適用済みの全タスク（日付を問わず全件）を表形式（チェックボックス／ID／タイトル／ステータス／親ID／開始予定／終了予定／完了日）で一覧表示し、行クリックで編集対象を切り替える。チェックボックスは複数選択（[PJ一括編集](#17-プロジェクトツリー表示)と、[1.13 編集フォーム](#113-編集フォームタイマー機能含む)の一括編集の対象）。

### B. データモデル

- **mainData**：日々のタスク・報告・勤務カレンダー等（列定義は`dataModel.js`の`MAIN_DATA_COLUMNS`）。AI秘書の仮登録行は`AI原案`／`AI確認`列を持つ（[1.9](#19-ai確認)参照）。
- **システム列**（2026-10-28〜）：行の種別などアプリ管理用の情報をオブジェクトで持つ列。種別なし（列が空）＝通常のタスク／`1日タスク`／`報告`（`報告区分`付き）／`勤務カレンダー`。旧「データ区分」「PARA区分」の2列と、報告用の「Input」「Output」の2列を統合したもので、旧形式のデータは読み込み時に自動変換する。報告行は種別のほかに`報告区分`・`報告先`（テーマ行：既定の報告先IDのカンマ区切り／タイミング行：報告先ID）・`テーマID`（エントリ行）・`報告状態`（エントリ行：`sN 予定|済 yyyy/mm/dd|見送り`を1行1件）を持つ。Infoタブの生データ表ではJSON文字列として表示・編集でき、Excel出力でもJSON文字列になる。
- **保存形式**：mainDataの各行は、空欄の列を省いて保存する（2026-10-28〜。読込時に全列を空欄で補うので、アプリ内では全列がある前提で扱う）。
- **masterData**：カテゴリ・タグ・プロジェクト・ステータス等の親子関係定義（`MASTER_DATA_COLUMNS`）。
- 親子関係（プロジェクト所属・繰返し親子）はすべて「親ID」列（`親ID`）1本の親ID方式で表現する。旧・フラット文字列の「プロジェクト」列は完全に廃止済み（[添付G](#g-構成変更履歴)参照）。

### C. データ読み書き・オフライン対応

- 読み込み：GitHub API → 成功時はテキスト＋SHAをLocalStorageにキャッシュ。失敗時はキャッシュから復元。
- 保存：ボタン押下で即座にLocalStorage更新 → GitHubへPUT送信。圏外失敗時もデータはローカルに保持され、ユーザーに通知。
- 自動保存：1分ごとに、トークン設定済み・データ読込済みかつ変更がある場合のみ自動的にGitHubへ保存（アラート等は出さない）。
- 保存競合（409）時：mainDataはID単位の3-wayマージ（`merge.js`）で自動解決、masterDataは片方のみ変更ならそちらを自動採用、両方変更されていた場合のみユーザーに選択を求める。

### D. タイムスタンプログ形式・実績時間の計算

- タイマー開始時：`YYYY/MM/DD HH:mm:ss-` を末尾に追記。
- タイマー停止時：`YYYY/MM/DD HH:mm:ss, ` を末尾に追記（開始と停止のペアで1区間）。
- 計測中判定：ログ末尾が `-` で終わっている状態。
- 実績時間は、ログ中の全区間の合計＋「補正時間」欄の値（分、正負可）で算出する。

### E. 1日タスク（DAYPLAN）の共通仕様

- [1.10](#110-日別タイムライン1日タスクdayplan)から同一のデータ（システム列 `{ 種別: '1日タスク' }` の特殊行、日付ごとに1件）を参照・編集する。通常のタスクとは`task.js`の`isDayPlanRow`／`isNormalTaskRow`で区別し、一覧・件数・カレンダー等の母集団には含めない。
- 内容欄に「`[列番号] HH:MM-HH:MM 内容`」または「`[列番号] HH:MM-HH:MM #ID ラベル`」の行を1行1件書式で保持し、`#ID`があれば既存タスクへのリンクとして扱う。先頭の`[列番号]`（1〜4）は省略可能で、省略された行（旧データ・1日タスクに未追加のタスクの表示など）は重なりに応じてどこかの列へ自動的に詰め込んで表示する（表示用のフォールバックであり、内容テキストは書き換わらない）。
- 列1は「開始予定・終了予定が既に時刻まで決まっているタスク」の定位置で、重なりを気にせずそのまま配置する。列2〜4は時間未定タスクの作業枠で、ドラッグ等で時間が重なった場合は自動的に押し出して重ならないよう調整する（詳細は[1.10](#110-日別タイムライン1日タスクdayplan)）。

### F. 日付・データ形式の表記ゆれ

- 日時は基本的に `YYYY/MM/DD HH:mm:ss`（スラッシュ区切り）で保持し、`<input type="date">` とやり取りする際のみ `YYYY-MM-DD`（ハイフン区切り）に変換する。
