# 開発方針：読書ビューア（プロトタイプ）

**Why:** myselfワークスペースの`book-reading`スキルで文字起こしした専門書の本文を、トークンを使わずに何度でも読み返せるようにするためのビューア。brainの「読書メモ」機能（本→章メモ→QAカード）とは別に、ページ単位の完全な逐語転記＋ページ画像との照合を主目的として独立させた（2026-09-27、ユーザー判断）。
**How to apply:** 新機能追加・変更時は必ずこのルールを参照すること。brain/cookと共通する設計思想（[ルートCLAUDE.md](../CLAUDE.md)参照）は重複説明を省略している。

---

## 1. ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | エントリポイント。DOM構造のみ |
| `css/style.css` | UIデザイン。常時表示バーはbrainと同一スタイル・文言（Excel出力／入力ボタンのみ非搭載） |
| `js/app.js` | メイン制御 |
| `js/modules/github.js` | GitHub API通信（`fetchFile`／`saveFile`。既読チェックの保存に`saveFile`を使う） |
| `js/modules/storage.js` | LocalStorageキャッシュ（`book_`接頭辞） |
| `js/modules/dataModel.js` | books.md／本ごとのファイルのFront Matter（JSON）パース、章・ページの並べ替え |

## 2. データ

- リモート: `palmelo2nd/app_data`リポジトリ `book/`配下。ローカルパス: `app_data/book/`
- **2ファイル構成**（2026-09-27、容量増加時にファイル単位で整理できるよう分離）
  - `book/books.md`：`bookData`（本の一覧。書名・著者・ステータス等）のみ。軽量で、起動時に必ず読み込む
  - `book/<書籍ID>.md`：本1冊ぶんの`chapterData`（章アンカー、`開始順序`でページ送り位置にジャンプ）／`pageData`（**1ページ＝1レコード**、`順序`・`表示ページ`・`PDFページ`・`本文`）。本を選んだ時に遅延読込する
- ページ単位にしている理由：本の実際のページ送り（前へ／次へ）をUIで再現するため。章単位でまとめて持たない
- `pageData`の各ページは`既読`（boolean）／`ハイライト`（`{text, offset, color, note?, question?, answer?}`の配列）を持つ。すべてアプリのUI操作で更新し、「保存」ボタンでGitHubへ書き戻す（`既読`・`ハイライト`は2026-09-28追加、`color`と`note`/`question`/`answer`は同日中に追加）
  - `color`：`yellow`＝TIPS（後で考察）／`blue`＝QA（一問一答、`question`＋`answer`を持つ）／`green`＝要点（体系的な抜き出し、`note`を持つ）／`pink`＝ラインのみ（本文タブ上での視覚的な強調のみ、専用タブ無し）。色の定義・意味・表示色は`js/app.js`の`MARKER_COLORS`に集約
  - `offset`を持たせている理由：同じ文字列がページ内に複数回出現する場合に、どの出現箇所を光らせる／解除するかを一意に決めるため。`text`も一緒に持たせているのは、後で検索・一覧表示する用途のため（ユーザー判断、2026-09-28）
  - マーカーの実装：`本文`（Markdown）自体は書き換えず、表示直前に`ハイライト`各要素の`text`を`<mark class="reader-highlight reader-highlight-<color>">`で挟み込んでからmarked.parseする（`js/app.js`の`withHighlightMarks`／`wrapNearestOccurrence`）。同じ文字列が複数箇所にある場合は`offset`に最も近い出現箇所だけを光らせる
  - マーカー箇所をクリックすると即削除ではなく、`編集`／`削除`／`キャンセル`のミニバナーを表示する（`pendingMarkClick`）。`編集`を押すと、そのマーク要素の中身を`Range`／`Selection` APIで丸ごとネイティブ選択状態にする（`findMarkElement`→`range.selectNodeContents`→`sel.addRange`）。これによりスマホのネイティブな開始・終了ハンドルがその場に出現し、独自のドラッグUIを実装せずに範囲調整ができる。編集中は`editingHighlight`に元のエントリを覚えておき、確定時（下記）に古いエントリを新しい範囲で置き換える。**編集開始直後はrenderPageView()を呼ばない**（呼ぶとDOMごと選択が消えるため）
  - UI：本文タブ上部に4色の丸ボタン（トグル）が並び、選択中の色がその色で塗られる。押すと「今どの色で引くか」を選んだ状態になり、もう一度押すとオフ。ネイティブのテキスト選択（スマホの開始点・終了点ハンドルも含む）をそのまま使って範囲を選ぶ。選択中は`::selection`をCSSで選んだ色に上書き表示する
  - **確定方式（重要）**：ボタンタップでの確定は採用していない。iOS Safariでは、テキスト選択後に別のボタンをタップすると、その最初のタップが「選択解除」に使われてしまいクリックハンドラに到達しないことがある（`preventDefault()`をmousedown/touchstartに仕込んでも防げないOSレベルの挙動と判明、2026-09-28に2回実装して2回とも失敗）。そのため`selectionchange`を監視する方式に統一しているが、確定タイミングは2段階で見直し済み：
    1. （初回実装、撤回）選択が800ms変化しなければ自動確定→広い範囲を選ぶ途中で誤確定してしまい、範囲の修正もできないという問題が発覚
    2. （現行）**選択が終わったタイミング（`selectionchange`でisCollapsedに戻った瞬間）で確定**する方式に変更。選択中は`pendingHighlight`に保持するだけで確定しないため、範囲をどれだけ時間をかけて選んでも（ハンドルでの調整を含め）指を離すまで確定されない。環境によって選択解除イベントが来ない場合の保険として3000msのフォールバックタイマーも残している
    - 「直前のマーカーを取り消す」ボタンは追加したが、「マーカーをクリックすれば消せるので不要では」というユーザー指摘と、後述の編集機能で代替できることから撤去済み
  - `book-reading`スキル側は、本を再開する際に既存の`ハイライト`を確認し、該当箇所を解説する運用（[[book-reading]]スキル参照）
- **本文自体の追加・更新は引き続きアプリ側では行わない**：`book-reading`スキル側で`.claude/skills/book-reading/scripts/book_data.py`を使ってページ・章を追記し、コミット・pushする運用。アプリからの書き込みは「既読」フラグのみに限定している

## 3. 常時表示バー（brainとの相違点）

- brainと同じ位置づけの「読込」「保存」「トークン入力」「同期ステータス」「キャッシュ更新」「バージョン表示」を踏襲
- 「保存」ボタンは、トークンのLocalStorage保存に加えて、既読チェックなど未保存の変更があれば選択中の本のファイル（`book/<書籍ID>.md`）へGitHub APIで書き戻す（brainの「保存」相当。ただし本文自体は編集不可、既読フラグのみが書き込み対象）
- 保存競合（409）はbrainの3-wayマージではなく、cookと同じ簡易方式（「他の端末で更新されています。読込してから既読チェックをつけ直してください」とアラートするのみ）
- Excel出力／入力ボタンは搭載しない

## 3.5 本棚（複数の本のカード一覧、入口画面）

- 本が増えても破綻しないよう、`読込`直後は必ず本棚（`renderShelf`）を表示する。以前は左サイドバーに全ての本を「章一覧を常時展開したブロック」として縦に並べていたが、本が2冊目以降増えると章一覧同士が全展開で並び縦に長くなりすぎるため、2026-09-30に本棚画面を新設して置き換えた
- 本棚では`.content`領域に書名・著者/ステータス・進捗バーのカードを`books.md`の並び順でグリッド表示する（`.layout`に`shelf-mode`クラスを付け、サイドバーを非表示・contentのmax-widthを解除）。進捗％は各本の本文ファイル（`book/<書籍ID>.md`）を読まないと分からないため、カードは先に「読込中…」で即表示し、`loadBookDetail`完了後に非同期で埋める（`fillShelfCardProgress`）
- カードをクリックすると`openBook`で該当の本を開く。開いた後はサイドバーが「← 本棚」ボタン＋その本の章一覧（`renderBookSidebarShell`）に切り替わり、戻るボタンで`renderShelf()`に戻る
- `renderChapterList`自体は変更なし（サイドバー内の`.chapter-holder[data-book-id=...]`を探して章ボタンを差し込むだけの実装のため、単一本表示に切り替えても流用できた）

## 4. コンテンツ領域（上部タブ：サマリー／本文／TIPS／要点／QA）

- タブ定義は`js/app.js`の`TABS`配列（key・label・render関数）に集約。タブを増やす時はここに1エントリ追加するだけでよい
- **サマリータブ**：選択中の本の既読進捗を、全体＋章ごとの進捗バー（`計算はdataModel.jsの computeProgress`）で表示。章の範囲は`chapterData`の`開始順序`〜次の章の`開始順序`直前までのページ数で判定
- **本文タブ**：ページ送りビュー。ページ見出し部分に「読み終わった」チェックボックスと4色マーカーボタンを配置
- **TIPS／要点／QAタブ**（2026-09-28追加、`renderMarkerListView`）：本の全ページを横断して該当色の`ハイライト`を集め、引用＋「該当ページへ移動」ボタン＋編集欄（TIPS・要点は`note`、QAは`question`／`answer`）を並べる。編集欄への入力はその場で対象の`ハイライト`要素を直接書き換える（`selectedPages`とキャッシュは同じオブジェクト参照を共有しているため、保存時に反映される）
- タブの選択状態はモジュール変数`activeTab`で保持し、本を切り替えても維持する（章ジャンプ時・TIPS等からのページ移動時は本文タブに強制的に戻す）
