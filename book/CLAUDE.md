# 開発方針：読書ビューア（プロトタイプ）

**Why:** myselfワークスペースの`book-reading`スキルで文字起こしした専門書の本文を、トークンを使わずに何度でも読み返せるようにするためのビューア。brainの「読書メモ」機能（本→章メモ→QAカード）とは別に、ページ単位の完全な逐語転記＋ページ画像との照合を主目的として独立させた（2026-09-27、ユーザー判断）。
**How to apply:** 新機能追加・変更時は必ずこのルールを参照すること。brain/cookと共通する設計思想（[ルートCLAUDE.md](../CLAUDE.md)参照）は重複説明を省略している。

---

## 1. ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | エントリポイント。DOM構造のみ |
| `css/style.css` | UIデザイン。常時表示バーはbrainと同一スタイル・文言（Excel出力／入力ボタンのみ非搭載） |
| `js/app.js` | メイン制御 |
| `js/modules/github.js` | GitHub API通信（`fetchFile`／`saveFile`。既読チェックの保存に`saveFile`を使う） |
| `js/modules/storage.js` | LocalStorageキャッシュ（`book_`接頭辞） |
| `js/modules/dataModel.js` | books.md／本ごとのファイルのFront Matter（JSON）パース、章・ページの並べ替え |

## 2. データ

- リモート: `palmelo2nd/app_data`リポジトリ `book/`配下。ローカルパス: `app_data/book/`
- **2ファイル構成**（2026-09-27、容量増加時にファイル単位で整理できるよう分離）
  - `book/books.md`：`bookData`（本の一覧。書名・著者・ステータス等）のみ。軽量で、起動時に必ず読み込む
  - `book/<書籍ID>.md`：本1冊ぶんの`chapterData`（章アンカー、`開始順序`でページ送り位置にジャンプ）／`pageData`（**1ページ＝1レコード**、`順序`・`表示ページ`・`PDFページ`・`本文`）。本を選んだ時に遅延読込する
- ページ単位にしている理由：本の実際のページ送り（前へ／次へ）をUIで再現するため。章単位でまとめて持たない
- `pageData`の各ページは`既読`（boolean）を持つ。アプリの「読み終わった」チェックボックスで更新し、「保存」ボタンでGitHubへ書き戻す（2026-09-28追加）
- **本文自体の追加・更新は引き続きアプリ側では行わない**：`book-reading`スキル側で`.claude/skills/book-reading/scripts/book_data.py`を使ってページ・章を追記し、コミット・pushする運用。アプリからの書き込みは「既読」フラグのみに限定している

## 3. 常時表示バー（brainとの相違点）

- brainと同じ位置づけの「読込」「保存」「トークン入力」「同期ステータス」「キャッシュ更新」「バージョン表示」を踏襲
- 「保存」ボタンは、トークンのLocalStorage保存に加えて、既読チェックなど未保存の変更があれば選択中の本のファイル（`book/<書籍ID>.md`）へGitHub APIで書き戻す（brainの「保存」相当。ただし本文自体は編集不可、既読フラグのみが書き込み対象）
- 保存競合（409）はbrainの3-wayマージではなく、cookと同じ簡易方式（「他の端末で更新されています。読込してから既読チェックをつけ直してください」とアラートするのみ）
- Excel出力／入力ボタンは搭載しない

## 4. コンテンツ領域（上部タブ：サマリー／本文、2026-09-28追加）

- **サマリータブ**：選択中の本の既読進捗を、全体＋章ごとの進捗バー（`計算はdataModel.jsの computeProgress`）で表示。章の範囲は`chapterData`の`開始順序`〜次の章の`開始順序`直前までのページ数で判定
- **本文タブ**：既存のページ送りビュー。ページ見出し部分に「読み終わった」チェックボックスを追加
- タブの選択状態はモジュール変数`activeTab`で保持し、本を切り替えても維持する（章ジャンプ時は本文タブに強制的に戻す）
