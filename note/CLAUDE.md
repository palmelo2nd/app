# 開発方針：ナレッジ（note）

**Why:** brainから外したナレッジ（brain_tempに仮置きしていた72件）の移行先として作った、Obsidian風の自作ナレッジアプリ（2026-11-06作成、brain #1388）。ほぼiPhoneで、手順・コマンド・社内ルール・連絡先などを調べて見るのが主な使い方。Claude（秘書など）が.mdファイルを直接読み書きすることも想定する。
**How to apply:** 新機能の追加・変更のときに読む。計画と経緯は`app_data/docs/note/261106_ナレッジアプリ最小版.md`（段階①〜③のタスク・決まったこと）。共通ルールは[ルートCLAUDE.md](../CLAUDE.md)、見た目は[DESIGN.md](../DESIGN.md)。

## 2. データ

- 保存先：`app_data/note/`（`app_data_repo`に従う。diaryと同じ）。**ノート1枚＝1つの.md**、ファイル名は`<ID>_<作成時の題名>.md`
- 先頭にJSONのFront Matter（book・diaryと同じ形、1行）：`{"id","title","category","tags","created","updated"}`。日時は`yyyy/mm/dd HH:MM`
  - **題名は`title`が正。ファイル名は作成後に変えない**（Why：GitHub上の改名は削除＋作成の2操作で、途中で失敗すると二重・欠けが出るため）
  - IDは`n`＋yymmddHHMMSS（新規）、移行分は`n`＋brain_tempのID（4桁ゼロ埋め）
  - ファイル名で置き換える文字は`\ / : * ? " < > |`と改行・タブだけ（`_`へ）。題名部分は30文字まで
  - Front Matterが無い・壊れている.mdも本文だけのノートとして読む（Claudeが手で置いたファイルなど）
- **How to apply:** Claudeが直接ノートを足すときも、上の形（1行のJSON Front Matter＋本文、ファイル名`<ID>_<題名>.md`）で書くこと。

## 3. 読み込み・保存（オフラインファースト）

- 読込：Contents APIのフォルダ一覧（各ファイルのSHA付き）を1回取り、端末のSHAと違うノートだけ本文を取り直す（同時6件）。一覧・本文はLocalStorageに持ち、圏外でも閲覧・検索・編集ができる
  - フォルダ一覧は1,000件まで。超えたらGit Trees APIに切り替える（stockの`listFilesRecursive`）
- 保存：ノート単位でPUT。**送るときのSHAは「編集を始めたときのSHA」**（`editState.baseSha`）。読込が裏で走ってノートが新しくなっても、編集前の版を基準に衝突を調べるため
- 圏外・トークン無し：端末に「未送信」（`note_pending`）として残し、次の「読込」か上のバーの「保存」で送る。未送信を何度も直した場合も、最初の未送信の基準SHAを使い続ける
- 衝突（409／422）：上書きしない。ノートに通知を出し、「GitHubの版を読み込む（端末の変更は捨てる）」か「端末の版を別のノートとして保存」を選ばせる
- 編集中の内容は入力のたびに下書き（`note_drafts`）として残す（iPhoneでタブが再読み込みされても消えないように）
- 画面はURLの`#<ノートID>`で切り替える（iPhoneの戻る操作で一覧に戻れるように）

## 4. 表示

- Markdownは自作の`renderMarkdown`。対応：見出し・段落（1行の改行はそのまま）・箇条書き（入れ子・番号・チェック）・引用・区切り線・コードブロック（「コピー」ボタン）・表・インラインコード・太字・取り消し線・リンク・URLの自動リンク。入力は必ずエスケープしてから変換する（ノートに書いたHTMLは文字として出す）
- 検索は題名・タグ・本文が対象。空白区切りでAND、全角／半角・大文字／小文字・カタカナ／ひらがなを同一視
- 一覧は更新日の新しい順。分類（すべて／仕事／自分）とタグで絞る
- **ノート間のリンク**：`[[題名]]`／`[[題名|表示名]]`／`[[題名#見出し]]`／`[[ID]]`。題名は`title`で引き、全角／半角・大文字／小文字は区別しない（`normTitle`）。無いノートへのリンクは薄い点線で出し、押すとその題名で新規作成する。コードの中の`[[…]]`はリンクにしない
- **バックリンク**：ノートの下に「このノートへのリンク」（このノートを`[[題名]]`か`[[ID]]`で参照しているノートと、その行）
- **題名を変えたとき**：ほかのノートの`[[旧題名]]`を書き換えるか確認し、書き換える（見出し・表示名の部分は残す。ファイル名は変えない）。書き換えも通常の保存（`persistNote`）と同じく、未送信・衝突の扱いになる
- **タグ**：属性の`tags`と、本文の「タグだけが書かれた行」（例`#手順 #読書`）のタグを合わせて使う（`allTags`）。**文章や箇条書きの途中の`#`はタグにしない**（Why：移行した実データに`git remote -v #一覧`のようなコマンドのコメントや、`- #背景`のようなプロンプトの見出し、`#(1)`のような番号があり、Obsidianと同じ規則だと誤ってタグになったため）。数字だけ（`#123`）と記号で始まるものもタグにしない。判定は`markdown.js`の`tagLineTags`1か所にまとめ、表示（`renderMarkdown`）と抽出（`noteModel.js`の`bodyTags`）の両方が使う
- **How to apply:** リンク・タグの規則を変えるときは、`tagLineTags`・`noteModel.js`の`RE_WIKILINK`と`markdown.js`の`[[…]]`の正規表現をそろえて直すこと。本文や属性を書き換える処理を足したら`invalidate(note)`を呼ぶこと（検索用の文字・リンク・タグの覚え書きを消すため）
