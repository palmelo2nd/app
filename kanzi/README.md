# 漢字学習アプリ

小学校配当漢字（学年別）を、読みクイズ・意味熟語クイズ・フラッシュカードで学習できるWebアプリ。HTML+CSS+JavaScript（バニラJS、ESモジュール）で構築し、[Second Brain](../brain/README.md)と同様にGitHub Pages想定・GitHubリポジトリへのデータ保存に対応する。

iOS/Android向けアプリとしてのストア販売を見据え、開発を以下の部門フォルダに分けて記録している（実装コード自体はこのリポジトリ直下＝「開発」部門にあたる）。

## 1. 対象漢字・データ構成

小学校で習う学年別配当漢字（1年〜6年、1006字）を収録。各漢字は「学年」「画数」「音読み」「訓読み」「意味」「熟語（2件程度）」を持つ。

漢字そのもののデータ（読み・意味・熟語）はユーザーごとに変わらないため、`data/kanjiMaster.json`としてアプリ本体（コードリポジトリ）に同梱している。学習の進捗（出題回数・正解回数など）だけを、Second Brainと同じデータリポジトリ（`palmelo2nd/app_data`の`kanzi/data.md`）にGitHub API経由で保存する。この分離の理由は[CLAUDE.md](./CLAUDE.md)の「2. データの分離方針」を参照。

現時点では、`kanjiMaster.json`側の日本語の「意味」は5,514字中5,474字（99.3%）まで到達（Wiktionaryでの直接取得74%＋英語グロスからの機械翻訳分。詳細は`CLAUDE.md`）。`jukugo.json`（熟語）は学年1〜6（小学校配当漢字）3,080件、4級〜2級（中学〜高校レベル）2,370件に加え、準1級・1級2,091件を新規収録し、合計7,541件に加え、2026-09-01に故事・諺728件を新規収録し合計8,269件（[18章](#18-既知の制約今後の拡張候補)参照）。

## 2. 級の選択とクイズタブ

画面上部の「対象級」プルダウンで、漢検10級〜1級のいずれか1つを選ぶ（2026-08-31、学年ベースの選択から刷新。`kanjiMaster.json`の「級」フィールドを直接見るため、学年からの近似では拾えなかった級のズレも正確に反映される）。選択はホーム・クイズ・意味熟語クイズ・フラッシュカード・成績のすべてのタブに共通で適用され、切り替えると出題中の問題やカードは作り直される。プルダウンの末尾には開発者専用の「開発」も選択肢として含まれる（[CLAUDE.md](./CLAUDE.md)「6. 開発タブ」参照）。

ナビゲーションの「クイズ」タブを開くと、選択中の級で実際に出題される漢検の公式ジャンル（漢字の読み・書取・部首部首名・筆順画数・送り仮名・対義語類義語・同音同訓異字・熟語の構成・誤字訂正・故事諺など、級によって異なる。出典は[00_市場調査/出題範囲（公式基準）.md](./00_市場調査/出題範囲（公式基準）.md)）に応じたサブタブが並ぶ。**2026-09-01時点で、15ジャンル全て実装済み**（3〜13章）。

## 3. 読みクイズ（漢字の読み）

「クイズ」タブの「漢字の読み」サブタブの中身。熟語を使った短い例文を表示し、文中でハイライトされた対象語の読みを答える。実際に文章の中で使われる形で読みを問うことで、より実践的な出題にしている。出題は、進捗が悪い（正答率が低い）漢字・未学習の漢字ほど選ばれやすい重み付き抽選（`js/modules/progress.js`の`calcWeight`）で行う。回答すると正誤と正解を表示し、「次の問題」で次へ進む。

**回答方式は4択ではなく、ひらがなの直接入力**（2026-09-02変更、実際の漢検が記述式のため）。問題文の下のテキスト入力欄にスマホ標準の日本語入力（フリック入力等）でそのまま読みを打ち込み、「こたえる」ボタン（またはEnterキー）で確定して正誤判定する（当初は自前の50音キーボードを用意したが、「スマホ標準のフリック操作の方が使いやすい」というフィードバックを受けて標準入力に切り替えた）。

例文データは学年1〜6（小学校配当漢字）・4級〜2級（中学〜高校レベル）・準1級〜1級（大学・専門レベル、故事・諺728件を含む）を含む全8,269件で完備済み（[18章](#18-既知の制約今後の拡張候補)参照）。

**10級〜6級では、熟語の例文に加えて単漢字の読み例文（`kanjiMaster.json`の`読み例`、10級131件・9級248件・8級303件・7級287件・6級252件）も出題対象に混ぜている**（2026-09-02追加）。実際の漢検の低い級では、まだ習っていない上位級の漢字を含む熟語をまるごと読ませるのではなく、対象漢字1文字だけの読みを問う出題が中心と分かったため（構成漢字が対象級以下の熟語の割合は10級5.4%・9級17.5%・8級27.3%・7級39.5%・6級53.3%のみだった）。いずれの級も単漢字プールと「構成漢字が全て対象級以下（下位級を含む）」に絞った熟語プールを合わせて出題し、`読み例`データが無い5級以降は従来どおり「対象級の漢字を1つでも含む」熟語プールのみで出題する（[CLAUDE.md](./CLAUDE.md)の開発履歴・8章参照。5級以降への展開は級が上がるほど緊急度が下がるため今後の課題）。

## 4. 書取クイズ（漢字の書取）

「クイズ」タブの「漢字の書取」サブタブの中身。読みクイズの逆で、例文中の対象語を読み（ひらがな）に置き換えて表示し、正しい漢字表記を4択で答える（例：「けいさつかんに<u>みち</u>をたずねる。」→「道／未知／満ち／御地」）。母集団の抽出・重み付き抽選・進捗反映は読みクイズ（3章）と完全に同じ仕組みを流用しており（`js/modules/quiz.js`の`buildWritingQuiz`）、対象語以外の高度な漢字へのふりがな表示も読みクイズと同様に付く。

## 5. 筆順クイズ（筆順・画数）

「クイズ」タブの「筆順・画数」サブタブの中身（現状は筆順のみ）。漢字を1画だけ太字（青色）で強調表示し、それが何画目に書く画かを4択で答える。漢字マスタとは別の`data/strokeOrder.json`（KanjiVG由来の筆順データ、約15MB）を使うため、初めてこのタブを開いたときだけ読み込みに少し時間がかかる（開発タブの筆順レビューと同じ遅延読み込みを共用）。表示はHanziWriterのアニメーション機能ではなく、`strokes`（塗りつぶし輪郭パス）を直接使った自前の静止画SVG描画（詳細は[CLAUDE.md](./CLAUDE.md)「6. 開発タブ」参照）。

## 6. 部首・部首名クイズ

「クイズ」タブの「部首・部首名」サブタブの中身（8級〜2級が対象、2026-09-01実装）。協会公式サイト・練習問題サイトを調査したところ、実際の出題は1字について「部首」と「部首名」の**両方**を答えさせる形式（3級以下はマーク式、準2級以上は記述式）だったため、独自の形式にせずこの内容を1画面に部首用・部首名用の2つの4択として再現した。両方に解答すると（両方正解して初めて）進捗に反映され、「次の問題」が押せるようになる（`js/modules/quiz.js`の`buildBushuQuiz`）。

## 7. 送り仮名クイズ

「クイズ」タブの「送り仮名」サブタブの中身（8級〜2級が対象、2026-09-01実装）。公式の出題形式「赤字のカタカナを漢字一字と送りがなに直す」に合わせ、読みをカタカナ表示（例：「ウカル」）にして見せ、正しい漢字＋送りがな表記を4択で答える（`js/modules/quiz.js`の`buildOkuriganaQuiz`）。`kanjiMaster.json`の`送り仮名例`データを使用。

## 8. 対義語・類義語クイズ

「クイズ」タブの「対義語」（8級・7級）／「対義語・類義語」（6級以降）サブタブの中身（2026-09-01実装）。公式の出題形式「ひらがなの語群から対義語・類義語を選び漢字に直す」を踏まえ、熟語を見せてその対義語（または類義語）を4択で答える（`js/modules/quiz.js`の`buildTaigigoRuigigoQuiz`）。`jukugo.json`の`対義語`/`類義語`データを使用するが、**2級以上はこのデータがほぼ無いため出題できない**（[18章](#18-既知の制約今後の拡張候補)参照）。

## 9. 同じ漢字の読み・同音異字・同音同訓異字クイズ

「クイズ」タブの「同じ漢字の読み」（8級）／「同音異字」（7級）／「同音・同訓異字」（6級以降）サブタブの中身（2026-09-01実装）。公式の例題を確認したところ、いずれも「文中のカタカナ部分に当てはまる、同じ読みで異なる漢字を文脈から選ばせる」という同一の出題内容だったため、単一の実装を共用する。例文中の対象語を読みに置き換えて見せ、同じ読みを持つ他の熟語（真の同音・同訓異字）を優先的に誤答候補にした4択で答える（`js/modules/quiz.js`の`buildHomophoneQuiz`）。

## 10. 三字熟語・四字熟語クイズ

「クイズ」タブの「三字熟語」（7級・6級）／「四字熟語」（5級以降）サブタブの中身（2026-09-01実装）。公式の出題形式「例文中のカタカナ部分を漢字に直して熟語を完成させる」に合わせ、書取クイズと同じ考え方で対象の熟語を読みに置き換えて見せ、正しい表記を4択で答える（`js/modules/quiz.js`の`buildJukugoTypeQuiz`）。`種別`='四字熟語'の対象は、2026-09-01の棚卸しにより公式基準の「典拠のある四字熟語」に該当する46件に絞り込み済み（[18章](#18-既知の制約今後の拡張候補)参照）。

## 11. 熟語の構成クイズ

「クイズ」タブの「熟語の構成」サブタブの中身（6級〜2級が対象、2026-09-01実装）。公式サイト・jitenon等の練習問題ページを調査したところ、実際の出題は「ア〜オの5分類の凡例表を常時提示したうえで、熟語1つがどれに当てはまるかを選ばせる」形式だったため、この内容をそのまま再現した。選択肢は熟語ではなく常に固定のア〜オ5つで、他ジャンルと異なりシャッフルしない（対策教材の慣習に合わせた、`js/modules/quiz.js`の`buildJukugoKouseiQuiz`）。`jukugo.json`の全二字熟語7,097件に付与済みの`構成`（ア〜オ）データを使用し、判定の確からしさが低い「確信度：低」のエントリも出題対象から除外していない（開発タブ「熟語の構成レビュー」で別途レビューできる、[CLAUDE.md](./CLAUDE.md)「6. 開発タブ」参照）。

## 12. 故事・諺クイズ

「クイズ」タブの「故事・諺」サブタブの中身（準1級・1級専用、2026-09-01実装）。公式審査基準（準1級・1級で「典拠のある四字熟語、故事成語・諺を正しく理解している」）と対策サイトの実問題を調査した結果、実際の出題形式は「諺・成語中の一部をカタカナ化して見せ、正しい漢字に直させる」書き取り形式で、書取・三字熟語・四字熟語クイズと同じ仕組み（`js/modules/quiz.js`の`buildJukugoTypeQuiz`）がそのまま使えると判明した。他ジャンルと異なり`語`は熟語全体ではなく諺・成語の中の空欄部分（1〜4字、`例文`＝諺・成語の全文自体）を指す点が特徴（詳細は[01_技術調査/故事諺データ調査.md](./01_技術調査/故事諺データ調査.md)参照）。

データはウィクショナリー日本語版のカテゴリ「故事成語」「日本語 ことわざ」（下位カテゴリを含め再帰的に収集、合計1,401ページ）から機械取得し、由来カテゴリタグから典拠（新設`出典`フィールド）も取得した。**「故事・諺」タブ自体は準1級・1級専用だが、そこに出題されるかどうかは対象語（空欄部分）の漢字が準1級・1級レベルかどうかで機械的に決まる**ため、当初は収集1,033件中対象級に到達する340件のみを想定していたが、「準1級でも易しい語の出題がある」というユーザー方針により**対象級を問わず重複・欠落の無い728件全てを`jukugo.json`に登録**した（残る305件は読み不明・確信度低・重複等の理由で除外。詳細は同調査ドキュメント7〜8章参照）。登録時、ウィクショナリーの`由来`タグに元号（`明治`「日本の元号の一つ」等、計43件）が混入していることが判明し除外した。準1級・1級に届かない語（例：「猿も木から落ちる」「鬼に金棒」等）は「故事・諺」タブには出現しないが、対応する低い級の読みクイズ・書取クイズでは通常どおり出題される。選択肢は`語`の文字数を揃えて誤答を選ぶよう`buildJukugoTypeQuiz`を拡張し、文字数だけで正解が分かってしまわないようにしている。

## 13. 誤字訂正クイズ

「クイズ」タブの「誤字訂正」サブタブの中身（5級以降が対象、2026-09-01実装）。公式の出題形式「文中の誤って使われている同じ読みの漢字を正しい漢字に直す」に合わせ、二字熟語の一方の文字を同じ読みの別の漢字に差し替えた文を見せ、正しい漢字を4択で答える（`js/modules/quiz.js`の`buildGojiTeiseiQuiz`）。誤字訂正だけは他ジャンルと異なり**専用の外部データが存在しない**ため、`kanjiMaster.json`の音読みデータと部品構成データ（IDS）を組み合わせて差し替え候補を機械生成した（詳細は[01_技術調査/誤字訂正データ調査.md](./01_技術調査/誤字訂正データ調査.md)参照）。

生成ロジックは、①差し替え候補の読みが対象の文字と完全一致すること、②差し替えた結果が別の実在する熟語にならないこと、③対象級が近い漢字であること、を必須条件とし、加えて④漢字の部品構成データ（[yi-bai/ids](https://github.com/yi-bai/ids)、MIT）から「同じ部品（音符）を共有する、または一方が他方を部品として含む」視覚的に紛らわしい候補を優先する。実際の漢検過去問16問を分析したところ、読みの一致は100%、視覚的な類似は50%の問題で見られたため、この設計を採用した。二字熟語7,097件中5,505件（78%）に候補を生成でき、うち65%（3,563件）は視覚的にも紛らわしい候補（`誤字候補_視覚類似度`が「高」または「中」）を持つ。開発タブ「誤字訂正レビュー」で視覚類似度別に絞り込みながら承認／保留／却下・内容修正ができる。

## 14. 意味・熟語クイズ

漢字の意味を4択で当てる問題と、熟語の空欄（例：「＿番」）に入る漢字を4択で当てる問題を、ランダムに出し分ける。意味・熟語データがある漢字のみが対象。対象漢字が4字未満の級を選ぶと、その旨のメッセージを表示する。

## 15. フラッシュカード

対象級から重み付き抽選で最大20枚のカードを作り、1枚ずつ表示する。カードをタップ／クリックすると裏面（音読み・訓読み・意味）が出て、「もう一度」「覚えた」で自己採点する（この自己採点も進捗に反映される）。最後まで進むと「最初からやり直す」で新しいセットを作れる。

## 16. 成績

対象級内の学習済み字数・平均正答率と、正答率が低い（かつ一定回数以上出題済みの）「苦手な漢字」を最大20件、正答率の低い順に表示する。

## 17. 設定・データの保存

GitHub Personal Access Token（Contents権限、`palmelo2nd/app_data`への読み書きが必要）を入力し、「読み込み」で進捗をGitHubから取得、「保存」でLocalStorageとGitHubの両方に反映する。

- クイズ・フラッシュカードで1問答えるたびに、進捗はLocalStorageへ即座に保存される（オフラインでも進捗は失われない）。GitHubへの反映は「保存」ボタンを押したときのみ行われる。
- 保存時にGitHub側が別端末等で更新されていた場合（409エラー）は、その旨を表示するので「読み込み」で最新化してから再保存する。

## 18. 既知の制約・今後の拡張候補
