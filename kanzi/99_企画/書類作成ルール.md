# 書類作成ルール

各部門フォルダ内の記録文書（主にREADME.md）を書くときの型。目的は「誰が後で読んでも、何を目的に・何が決まっていて・何が未着手かがすぐ分かる」こと。

## 各部門README.mdの基本構成

1. **タイトル**（`# 部門名`）と一言説明
2. **記録すること**：この部門で何を書き溜めるかの箇条書き（着手前でも先に定義しておく）
3. **本文**：調査結果・決定事項・比較表など（内容が増えたら見出しで章立てする）
4. **ステータス**：チェックボックス（`- [ ]` / `- [x]`）で進捗を明示。「（着手前）」のように一言で状態を書くだけでも可

## 表記ルール

- 見出し・箇条書き中心。長い散文で説明しない
- 決定事項には理由（なぜその選択か）を必ず添える。理由が抜けると、後で見返したときに再検討できない
- 未確認・未着手の項目は「TODO」ではなく`- [ ]`のチェックボックスで統一する（進捗が視覚的に分かる）
- 他部門・他フォルダへの参照は相対パスのMarkdownリンクで貼る（`[00_市場調査](../00_市場調査/README.md)`のように）。テキストだけで「〇〇部門を参照」と書かない
- 日付を記す場合は絶対日付（`2026-08-29`のように）で書く。「先週」「来月」等の相対表現は使わない

## 保留事項・後回しにしたTODOの書き方

調査や作業の途中で「これは今すぐでなくて良いが、後で深掘りしたい」という項目が出たら、忘れないようその場で該当部門のREADME.mdに`- [ ]`で書き残す（頭の中や会話ログだけに留めない）。書き方の型：

```
## 保留中の追加調査（TODO）／保留事項

- [ ] 何を・なぜ後回しにしたか（優先度や理由も一言添える）
```

着手したら`- [x]`にし、対応内容を一言添える。完了後も消さずに履歴として残す（何を検討した上で今の形になったかが後から追える）。

## 反省点・改善点の書き方（振り返りログ）

[振り返りログ.md](./振り返りログ.md)には、以下の形式で1エントリずつ追記する。

```
## YYYY-MM-DD 部門名
- 気づき／反省点：〜
- 改善案：〜（テンプレート側に反映するなら「→部門構成テンプレートに反映」等を書く）
```

まとめようとせず、気づいた時点で短くてもよいので追記する。後で`99_企画`側の一般化文書に反映する際に整理する。
