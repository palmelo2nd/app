# 開発方針：記憶カードアプリ（Webフロントエンド版）

**Why:** 再起動時にも一貫した設計・実装を維持するための厳格ルール集。[[project-brain-dev-policy]]（Second Brain全体の方針）と同じ思想を、本アプリ（個人用フラッシュカード・間隔反復学習ツール）向けに具体化したもの。
**How to apply:** 新機能追加・バグ修正・リファクタリング時は必ずこのルールを参照すること。

---

## 0. このアプリの位置づけ

日中に「覚えておきたい」と思った語彙・数学記号・長文などを記録し、ライトナー式の間隔反復（Leitner system）でゲーム感覚に復習するための**個人用**アプリ。kanziアプリと違い、ストア公開は想定していない（RELEASE_BUILDフラグ・Capacitor対応・審査対策等は不要）。GitHub Pagesで動く素のWebアプリとして完結する。

## 1. ファイル構成・命名規則

| ファイル | 役割 |
|---|---|
| `index.html` | エントリポイント。DOM構造のみ。直接JSロジックは書かない |
| `css/style.css` | UIデザイン・レイアウト定義 |
| `js/app.js` | メイン制御（管制塔）。イベント監視・DOM操作・画面描画に専念 |
| `js/modules/*.js` | 機能ロジック。1機能1ファイル、DOM操作禁止 |

### 現在の modules 構成
`github.js`（リモート通信。brainアプリと同一実装、owner/repo/pathを引数で受け取る汎用設計のため使い回している）／`storage.js`（LocalStorageキャッシュ。他アプリとの同一オリジン衝突を避けるため`memory_`プレフィックス付きキーを使用）／`dataModel.js`（Front Matterのパース／文字列化、列定義）／`srs.js`（ライトナー式の間隔反復ロジック：箱番号・次回復習日・正解/不正解回数・学習履歴の更新）／`quiz.js`（復習対象の抽出、苦手カード優先の出題順組み立て）

### modules の関数構成（必須4段落）
1. インポート（外部モジュール・ライブラリ）
2. インプット（引数でデータ・トークンを受け取る）
3. メイン機能（計算・データ加工・API通信）
4. アウトプット（`return` で結果を返す）

**禁止:** modules内でのDOM操作（`document.getElementById` 等）、OWNERやREPO名などの定数のハードコード（必ずインプットとして受け取る。定数自体は`js/app.js`側で管理する）。

## 2. データ構造・操作ルール

### データファイル
- リモートのデータ本体は GitHub リポジトリ `palmelo2nd/app_data` 内 `memory/data.md`。brainと同じFront Matter形式（`---`で囲んだJSON、`mainData`/`masterData`配列）。
- アプリ本体のコードは別リポジトリ（`palmelo2nd/app`、GitHub Pages）で管理する。コードとデータは別リポジトリのため、変更時はそれぞれ個別にコミット・pushする。
- ローカルパス: コード = `app/memory`、データ = `app_data/memory`（`data.md`）。

### mainDataの列（`dataModel.js`の`MAIN_DATA_COLUMNS`）
`ID` / `種別`（`語彙`｜`数学記号`｜`長文`。タブ切替に使う。新しい種別を増やす場合はUIのタブ配列に追加するだけでよい設計） / `表面` / `裏面` / `タグ` / `出典` / `作成日時` / `更新日時` / `箱番号`（1〜5のライトナー箱） / `次回復習日`（`YYYY/MM/DD`） / `正解回数` / `不正解回数` / `学習履歴`（`{日時, 結果}`の配列、`結果`は`覚えた`｜`間違えた`）

### ライトナー式間隔反復（`srs.js`）
箱1→1日後、箱2→3日後、箱3→7日後、箱4→14日後、箱5→30日後（以後30日を繰り返す）。正解で箱を1つ進め（上限5）、不正解で箱1に戻す。次回復習日 <= 今日のカードが「復習対象」。

### 出題の重み付け（`quiz.js`）
kanziアプリの`progress.js`（`calcWeight`/`getWeakKanji`と同じ考え方）を踏襲し、正答率が低いカードほど出題順が先になるよう重み付きシャッフルする。

### オフライン対応
brain/kanziと同じ「LocalStorageへ即時保存→GitHubへPUT」方式。ただし本アプリはbrainのような複数端末間の3-wayマージ（`merge.js`相当）は実装していない（個人の単一端末利用を前提とした簡易版）。保存時に409（競合）が出た場合は、自動マージせず「読み込みボタンで最新化してください」と案内するのみ。**複数端末で同時編集する運用が増えてきたら、brainのmerge.jsを移植する形で3-wayマージ対応を検討すること。**

### AI秘書からの入力について
myself workspaceの`daily-capture-sync`スキル経由で、日中に「覚えたい」と挙がった語彙・数学記号・長文が、夜の振り返りでこのアプリのmainDataへ追加されることがある（[[project_brain_ai_input_marker]]参照）。追加時は本アプリの新規カードと同じ形式（`箱番号:1`・`次回復習日:当日`から開始）で登録する。
