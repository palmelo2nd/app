## 1. 料理タブ

料理（レシピ）を1件1行で管理する中心タブ。

- **一覧・フィルタ**：カテゴリ／タグ／時間帯タグ（朝・昼・夜等）／難易度（易・中・難）／ステータス／調理時間（○分以内）で絞り込み。一覧は行ごとにチェックボックスがあり、複数選択して[買い物リスト](#23-買い物リスト)の対象にできる。

### 1.1 見るビュー／編集の分離

一覧から料理を選択すると、まず**見るビュー**（読み取り専用）が表示される：名称・カテゴリ・時間帯・想定人数・調理時間・難易度・ステータスの概要、材料、使う調理器具、前処理、作り方（番号付き手順）、[調理を開始](#13-調理を開始調理進行モード)ボタン、[調理ログ](#14-調理ログ)、この料理を含む献立の逆引き。調理中に見たい情報だけがまとまり、余計な入力欄は表示されない。

内容を編集したい時だけ、下の閉じた「編集」エクスパンダーを開く（名称〜ステータスの入力欄、材料リスト・使用調理器具・前処理・調理手順の編集、新規／適用／削除ボタン）。何も選択していない時（新規登録時）は編集エリアが自動的に開く。

### 1.2 材料リスト・使用調理器具・調理手順（編集エリア）

- **材料リスト**：行追加・削除できる表形式で、既存の食材から選択（食材IDで紐付け）＋分量（自由記述）＋備考を登録する。食材の名称やノウハウを更新すると、この参照経由で常に最新の食材情報とつながる。
- **使用する調理器具**：登録済み調理器具のチェックボックス一覧から、この料理で使うものを選択する。
- **調理手順**：行追加・削除できる表形式で、手順の内容と所要時間（分）を登録する。手順番号は自動採番。合計時間はリアルタイム表示される。

### 1.3 調理を開始（調理進行モード）

見るビューの「▶ 調理を開始」ボタンで、登録済みの調理手順をチェックリスト形式で表示し、開始からの経過時間をタイマー表示する。手順をこなしながらチェックを付けていき、「終了する」を押すとパネルが閉じ、[調理ログ](#14-調理ログ)の日時欄に現在時刻が自動入力されメモ欄にフォーカスが移る。料理を選び直す／新規にすると、実行中のタイマーは必ず停止する（裏で動き続けない）。

### 1.4 調理ログ

見るビュー内で、日時／出来栄え（★1〜5）／メモ（変えた点・気づき）／写真URL（任意）を入力し「記録する」を押すと、その場でデータへ即時保存される（別途「適用」を押す必要はない）。ログの件数が「作った回数」として一覧・見るビューに表示され、レシピを繰り返し改善していく際の根拠になる。

## 2. 献立タブ

食材を1件1行で管理する。

- **一覧・フィルタ**：カテゴリ（野菜／肉／魚介／主食／調味料／乳製品・卵／その他等、マスタで追加可）・タグ検索で絞り込み。
- **編集フォーム**：名称／カテゴリ／タグ／前処理・切り方ノウハウ／保存方法・注意点／代替食材／備考。
- **逆引き**：詳細を選択すると「この食材を使う料理」一覧を表示する（料理側の材料リストを食材IDで検索）。
- **削除時の後処理**：削除すると、全料理の材料リストから当該食材への参照も自動的に取り除かれる。

---

## 2. 調理器具タブ

調理器具を1件1行で管理する。

- **一覧・フィルタ**：カテゴリで絞り込み。

- **逆引き**：詳細を選択すると「この調理器具を使う料理」一覧を表示する。
- **削除時の後処理**：削除すると、全料理の使用調理器具リストから当該器具への参照も自動的に取り除かれる。

## 3. 料理タブ

料理（レシピ）を1件1行で管理する中心タブ。

- **一覧・フィルタ**：カテゴリ／タグ／時間帯タグ（朝・昼・夜等）／難易度（易・中・難）／ステータス／調理時間（○分以内）で絞り込み。一覧は行ごとにチェックボックスがあり、複数選択して[買い物リスト](#43-買い物リスト)の対象にできる。
- **編集フォーム基本項目**：名称／カテゴリ／タグ／時間帯タグ／想定人数／調理時間（分）／難易度／ステータス（下書き／試作中／完成／定番、マスタで追加可）。

### 3.1 材料リスト

行追加・削除できる表形式で、既存の食材から選択（食材IDで紐付け）＋分量（自由記述）＋備考を登録する。食材の名称やノウハウを更新すると、この参照経由で常に最新の食材情報とつながる。

### 3.2 使用する調理器具

登録済み調理器具のチェックボックス一覧から、この料理で使うものを選択する。

### 3.3 調理手順

行追加・削除できる表形式で、手順の内容と所要時間（分）を登録する。手順番号は自動採番。合計時間はフォーム内にリアルタイム表示される。

### 3.4 調理を開始（調理進行モード）

「▶ 調理を開始」ボタンで、登録済みの調理手順をチェックリスト形式で表示し、開始からの経過時間をタイマー表示する。手順をこなしながらチェックを付けていき、「完了して調理ログに記録する」で終了すると、[調理ログ](#35-調理ログ)の日時欄に現在時刻が自動入力される（出来栄え・メモは手動入力）。

### 3.5 調理ログ

作るたびに「日時／出来栄え（★1〜5）／メモ（変えた点・気づき）／写真URL（任意）」を追記できる実施記録。ログの件数が「作った回数」として一覧・編集フォームに表示され、レシピを繰り返し改善していく際の根拠になる。個別のログ行は削除も可能。

## 4. 献立タブ

複数の料理を組み合わせた献立を1件1行で管理する。料理タブと同じく、一覧から選択すると見るビュー（名称・時間帯・想定人数・ステータスの概要、構成する料理一覧、[調理進行](#22-この献立を作る調理進行モード)・[買い物リスト](#23-買い物リスト)ボタン）が表示され、編集は下の閉じた「編集」エクスパンダーで行う。

- **一覧・フィルタ**：時間帯タグ／ステータスで絞り込み。

### 2.1 構成する料理（編集エリア）

行追加・削除できる表形式で、登録済みの料理から選択（料理IDで紐付け）＋役割（主菜／副菜／主食／汁物／デザート／その他、自由入力可）を登録する。

### 2.2 この献立を作る（調理進行モード）

見るビューの「▶ この献立を作る」ボタンで、構成する各料理の調理手順の合計所要時間を比較し、最も時間がかかる料理を基準に「他の料理は全体開始から何分後に着手すれば同時に仕上がるか」を算出（`cook.js`の`computeMealPlanTimeline`）。各料理の手順をチェックリスト形式でまとめて表示し、全体の経過時間タイマーも表示するため、料理タブへ行き来せずこの画面だけで複数品を同時進行できる。献立を選び直す／新規にすると、実行中のタイマーは必ず停止する。

### 2.3 買い物リスト

見るビューの「買い物リストを作る」ボタンで、構成する全料理の材料リストを食材ごとに集計し、「食材名：どの料理でどれだけ使うか」の一覧を表示する（`cook.js`の`computeShoppingList`）。分量は自由記述のため数量の自動合算はせず、料理ごとの使用量を並べて表示する方式。[料理タブ](#1-料理タブ)側でも、複数の料理をチェックボックスで選んで同様のリストを作成できる。

## 共通機能・添付資料

### A. 上部バー（全タブ共通）

| 要素 | 内容 |
|---|---|
| 警告バナー | マスタデータの整合性チェック（`master.js`の`computeMasterWarnings`）で問題が検出された場合に表示。未登録の変数・存在しない食材/調理器具/料理IDへの参照などを検出する |
| トークン入力 | GitHub Personal Access Tokenをパスワード欄に入力。読込・保存・[Info](#5-info)のREADME取得に共通で使う（`app_data`・`app`両リポジトリへの権限が必要）。読込・保存・Excel出力・Excel入力のいずれかを実行するたびに、その時点の入力値をLocalStorageへ保存する |
| 読込／保存 | 「読込」：GitHubから最新データを取得。「保存」：現在のデータをGitHubへ保存 |
| 出力／入力 | Excel（.xlsx）としてエクスポート／インポート（`excel.js`） |
| キャッシュ更新 | ブラウザキャッシュが古いままの場合に、キャッシュバスター付きURLで強制リロードする |
| バージョン表示 | 現在読み込まれているアプリのバージョン（`vN`）を表示 |
| 同期ステータス表示 | オンライン（最新）／オフライン（未同期）のバッジ表示 |

### B. データモデル

食材・調理器具・料理・献立は列構成が大きく異なるため、brainのような1テーブル混在ではなく、テーブル（配列）自体を分けている（2026-09-20変更、詳細は[CLAUDE.md](./CLAUDE.md)参照）。

- **ingredientData**（食材）／**toolData**（調理器具）／**dishData**（料理）／**mealPlanData**（献立）：それぞれ独立した配列（列定義は`dataModel.js`の`INGREDIENT_COLUMNS`/`TOOL_COLUMNS`/`DISH_COLUMNS`/`MEALPLAN_COLUMNS`）。IDはテーブルごとに独立採番。
- **masterData**：カテゴリ・時間帯タグ・ステータス等の選択肢定義、および変数（列）名の自己登録（`MASTER_DATA_COLUMNS`）。
- 料理内の食材・調理器具、献立内の料理は、すべてID参照で紐付ける（参照先のテーブルは列の意味から一意に決まる。[CLAUDE.md](./CLAUDE.md)の構造化フィールド一覧参照）。

### C. データ読み書き・オフライン対応

- 読み込み：GitHub API → 成功時はテキストをLocalStorageにキャッシュ。失敗時はキャッシュから復元。
- 保存：ボタン押下で即座にLocalStorage更新 → GitHubへPUT送信。圏外失敗時もデータはローカルに保持。
- 自動保存：1分ごとに、トークン設定済み・データ読込済みかつ変更がある場合のみ自動的にGitHubへ保存する。
- 保存競合（409）時：brainのような自動マージは未実装。「読込してから編集し直してください」とアラートするのみ（[CLAUDE.md](./CLAUDE.md)参照）。
