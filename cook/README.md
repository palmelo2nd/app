## 1. 料理タブ（メイン）

アプリ起動時に開くメインタブ。**食材DB・調理器具とは一切連携せず**、料理を1件1行で「名称・材料・作り方・メモ」だけのシンプルな形で登録・編集し、実際に調理中に参照することに特化している（2026-10-10、方針変更）。

項目は名称・材料・作り方・メモの4つのみ。カテゴリ・タグ・時間帯・難易度・ステータス・調理ログ・調理進行モードなどは持たない（これらが必要な場合は[2. 開発中](#2-開発中食材db連携の既存機能の格納庫)の「料理（旧・詳細版）」を使う）。

### 1.1 材料・作り方の行編集

- **材料**：1行＝「食材／数量／単位」の3つの入力欄＋削除ボタン（食材DBとは連携しない自由記述）。下の「＋ 材料を追加」で行を増やせる。カンマ区切りなどを手入力する必要はない。
- **作り方**：1行＝自由記述の手順1つ＋削除ボタン。番号（1. 2. …）は保存せず、一覧・編集画面の表示時に行の順番から自動で振る。下の「＋ 手順を追加」で行を増やせる。

### 1.2 全文キーワード検索

一覧の上の検索欄に入力すると、名称・材料（食材／数量／単位）・作り方・メモをまとめた全文に対してキーワード一致で絞り込む。スペース区切りで複数キーワードを入れるとAND検索になる（例：「なす 味噌」で、材料に“なす”を含みメモに“味噌”を含む料理も両方ヒット）。実際に調理中に「この食材を使う料理は何だったか」を素早く探す用途を想定。

一覧テーブルは一定件数（目安10行）を超えると内部スクロール表示になり、ページ全体が間延びしない（[ルートCLAUDE.md](../CLAUDE.md)のUI/UX設計方針に準拠）。

## 2. 開発中（食材DB連携の既存機能の格納庫）

[1. 料理タブ](#1-料理タブメイン)をシンプルに保つため、食材DB・調理器具DBと連携する既存機能はすべてこの「開発中」タブの中のサブタブへ移動した（2026-10-10）。コード・データは変更していないため、将来「表記ゆれ整理」「食材DBとのID連携」「献立機能の拡張」に取り組む際はここから再開する。`料理`タブと同じ`dishData`テーブルを共有しているため、片方で登録した料理はもう片方の一覧にもそのまま表示される。

### 2.1 料理（旧・詳細版）

料理（レシピ）を1件1行で管理する、食材ID・調理器具IDへの参照を持つ詳細版。

- **一覧・フィルタ**：カテゴリ／タグ／時間帯タグ（朝・昼・夜等）／難易度（易・中・難）／ステータス／調理時間（○分以内）で絞り込み。一覧は行ごとにチェックボックスがあり、複数選択して買い物リストの対象にできる。
- **アイデアメモ**：最上部のテキストエリア＋「メモする」ボタンで、気になったレシピを一言だけ残してステータス「下書き」で即保存（brainのINBOXと同じ発想）。「下書きを整理」ボタンで下書きだけに絞り込める。
- **見るビュー／編集の分離**：一覧から選択するとまず読み取り専用の「見るビュー」（材料・使う調理器具・前処理・作り方・調理ログ等）が表示され、編集したい時だけ下の閉じた「編集」エクスパンダーを開く。
- **材料リスト**：食材IDで食材タブの行と紐付ける。未登録の食材は「＋ 食材を即席登録して追加」欄でその場で登録・紐付けできる。
- **調理を開始**：登録済みの調理手順をチェックリスト形式で表示し、経過時間をタイマー表示する調理進行モード。終了すると調理ログ入力にフォーカスが移る。
- **調理ログ**：日時／出来栄え（★1〜5）／メモ／写真URLを記録し、「作った回数」として表示される。
- **買い物リスト**：一覧でチェックした複数料理の材料リストを食材ごとに集計して表示する。

### 2.2 かんたん

[2.1 料理（旧・詳細版）](#21-料理旧詳細版)は項目数が多いため、同じ`dishData`を共有しつつ「名称・材料・作り方・メモ」だけの最小入力で登録・編集できる軽量タブ（2026-10-05追加）。材料・作り方は`簡易材料`/`簡易手順`列に自由記述のテキストとして保存する（[1. 料理タブ](#1-料理タブメイン)の`材料行`/`手順行`＝行編集・JSON配列形式とは別の列）。一覧は名称の部分一致検索のみ。

### 2.3 献立

複数の料理を組み合わせた献立を1件1行で管理する。

- **構成する料理**：登録済みの料理からID参照で選択し、役割（主菜／副菜等）を付ける。
- **この献立を作る**：構成する各料理の調理手順の合計所要時間を比較し、全料理が同時に仕上がるよう各料理の着手タイミングをまとめて表示する調理進行モード。
- **買い物リスト**：構成する全料理の材料をまとめて集計する。

### 2.4 食材

食材を1件1行で管理する。カテゴリ・タグ・前処理ノウハウ・保存方法・代替食材・備考を持ち、「この食材を使う料理」の逆引き表示、削除時の参照自動解除、表記ゆれ（「なす」「なすび」等）の統合機能を備える。

### 2.5 調理器具

調理器具を1件1行で管理する。カテゴリ・使い方/注意点・備考を持ち、「この調理器具を使う料理」の逆引き表示、削除時の参照自動解除を備える。

### 2.6 Info

コードリポジトリの[`README.md`](./README.md)（このドキュメント自体）を、アプリ内でMarkdownとして表示する。「再読込」ボタンでGitHub APIから最新版を取得する。

## 共通機能・添付資料

### A. 上部バー（全タブ共通）

| 要素 | 内容 |
|---|---|
| 警告バナー | マスタデータの整合性チェック（`master.js`の`computeMasterWarnings`）で問題が検出された場合に表示。未登録の変数・存在しない食材/調理器具/料理IDへの参照などを検出する |
| トークン入力 | GitHub Personal Access Tokenをパスワード欄に入力。読込・保存・[Info](#26-info)のREADME取得に共通で使う（`app_data`・`app`両リポジトリへの権限が必要）。読込・保存・Excel出力・Excel入力のいずれかを実行するたびに、その時点の入力値をLocalStorageへ保存する |
| 読込／保存 | 「読込」：GitHubから最新データを取得。「保存」：現在のデータをGitHubへ保存 |
| 出力／入力 | Excel（.xlsx）としてエクスポート／インポート（`excel.js`） |
| キャッシュ更新 | ブラウザキャッシュが古いままの場合に、キャッシュバスター付きURLで強制リロードする |
| バージョン表示 | 現在読み込まれているアプリのバージョン（`vN`）を表示 |
| 同期ステータス表示 | オンライン（最新）／オフライン（未同期）のバッジ表示 |

### B. データモデル

食材・調理器具・料理・献立は列構成が大きく異なるため、brainのような1テーブル混在ではなく、テーブル（配列）自体を分けている（2026-09-20変更、詳細は[CLAUDE.md](./CLAUDE.md)参照）。

- **ingredientData**（食材）／**toolData**（調理器具）／**dishData**（料理）／**mealPlanData**（献立）：それぞれ独立した配列（列定義は`dataModel.js`の`INGREDIENT_COLUMNS`/`TOOL_COLUMNS`/`DISH_COLUMNS`/`MEALPLAN_COLUMNS`）。IDはテーブルごとに独立採番。
- **masterData**：カテゴリ・時間帯タグ・ステータス等の選択肢定義、および変数（列）名の自己登録（`MASTER_DATA_COLUMNS`）。
- `dishData`は[1. 料理タブ](#1-料理タブメイン)用の`材料行`/`手順行`（JSON配列、食材DB非連携）と、[2.1 料理（旧・詳細版）](#21-料理旧詳細版)用の`材料リスト`/`調理手順`（JSON配列、食材ID参照）、[2.2 かんたん](#22-かんたん)用の`簡易材料`/`簡易手順`（自由記述テキスト）の3系統の材料・手順列を同時に持つ。同じ料理行でも、どのタブから見るかで表示される項目が異なる。
- 料理内の食材・調理器具、献立内の料理は、すべてID参照で紐付ける（参照先のテーブルは列の意味から一意に決まる。[CLAUDE.md](./CLAUDE.md)の構造化フィールド一覧参照）。

### C. データ読み書き・オフライン対応

- 読み込み：GitHub API → 成功時はテキストをLocalStorageにキャッシュ。失敗時はキャッシュから復元。
- 保存：ボタン押下で即座にLocalStorage更新 → GitHubへPUT送信。圏外失敗時もデータはローカルに保持。
- 自動保存：1分ごとに、トークン設定済み・データ読込済みかつ変更がある場合のみ自動的にGitHubへ保存する。
- 保存競合（409）時：brainのような自動マージは未実装。「読込してから編集し直してください」とアラートするのみ（[CLAUDE.md](./CLAUDE.md)参照）。
